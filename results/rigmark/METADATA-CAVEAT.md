# Metadata caveat — appliance block in these receipts

The `run.appliance` block in the receipts dated 2026-10-01 (all five) was generated by
`scripts/rigmark/metadata.py` with a HARDCODED COMMON block inherited from the flint
(TP2, 2-node) template:

    hardware: "2x NVIDIA DGX Spark (GB10, 128 GB unified memory each)"
    topology: "TP2 across two nodes, direct-connect ConnectX-7 RoCE, no switch"

It also snapshots env from `config/prod.env` (flint's config) because run.sh never
passed `--config`, so "4 batch slots" and the flint pool size appear there too.

GROUND TRUTH for these runs (verified independently):
  - Engine boot log: "rank 0 of 4" (r0), containers glm53-tf-r1/r2/r3 live on
    gx10-dc90 / spark-3ff5 / gx10-2ca4
  - Context/slots per receipt row = the engine's own runtime report (524288, 12 slots etc.)
  - The NUMBERS (tok/s, TTFT, gates) are unaffected — they were measured against the
    live endpoint; only the descriptive appliance metadata is mislabeled.

Fixed on the head (2026-10-01): COMMON now says 4x DGX Spark / TP4 ring, and run.sh
passes `--config "${CONFIG:-config/prod.env}"` so future receipts snapshot the active
config. Existing receipts left as-is; this file is the errata.
